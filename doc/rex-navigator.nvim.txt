1. rex-navigator.nvim                  *rex-navigator.nvim-rex-navigator.nvim*

**rex-navigator.nvim** lets you move between Neovim splits and Rex
<https://www.superlogical.com/rex> panes with the same keys, `<C-h>`, `<C-j>`,
`<C-k>`, and `<C-l>`. It is vim-tmux-navigator
<https://github.com/christoomey/vim-tmux-navigator> for Rex.

The plugin has two halves that work together:

- **Rex side:** `ctrl-h/j/k/l` moves between Rex panes, unless Neovim is the focused program. Then the key goes through to Neovim.
- **Neovim side:** the keys move between Neovim splits. At the last split in a direction, Neovim asks Rex to focus the next pane over.


REQUIREMENTS              *rex-navigator.nvim-rex-navigator.nvim-requirements*

- Neovim >= 0.10.0
- Rex <https://www.superlogical.com/rex>


INSTALLATION              *rex-navigator.nvim-rex-navigator.nvim-installation*


NEOVIM ~

Install **rex-navigator.nvim** with your preferred plugin manager. Using
lazy.nvim <https://github.com/folke/lazy.nvim>:

>lua
    {
      'wassimk/rex-navigator.nvim',
      version = '*',
      lazy = false,
      config = true,
    }
<


  [!NOTE] Load the plugin at startup. `setup()` installs the normal-mode
  `<C-h/j/k/l>` mappings and starts OSC reporting over SSH, so Rex can forward
  the first navigation key to Neovim.

REX ~

Rex has no plugin manager, but its configuration can `require` Lua files that
sit beside `~/.config/rex/init.lua`. Link the Rex side of the plugin there, so
it stays up to date with the Neovim plugin:

>shell
    ln -s ~/.local/share/nvim/lazy/rex-navigator.nvim/rex/rex-navigator.lua ~/.config/rex/rex-navigator.lua
<

Then load it in `~/.config/rex/init.lua`:

>lua
    require('rex-navigator').setup()
<

Apply the change with `rex config reload`.


CONFIGURATION            *rex-navigator.nvim-rex-navigator.nvim-configuration*


NEOVIM ~

These are the defaults:

>lua
    require('rex-navigator').setup({
      -- continue from the opposite edge when no Rex pane lies that way
      wrap = false,
      -- publish navigation over SSH when no local Rex session is available
      osc = 'auto',
    })
<

`setup()` installs `<C-h/j/k/l>` in normal mode. To customize a mapping,
override it after calling `setup()` using `navigate('h')`, `navigate('j')`,
`navigate('k')`, or `navigate('l')`:

>lua
    vim.keymap.set('n', '<C-h>', function()
      require('rex-navigator').navigate('h')
    end)
<

Set `osc = true` to force OSC reporting (for example, if Rex environment
variables are forwarded over SSH), or `osc = false` to use the local Rex CLI
transport instead. Configure this when calling `setup()` at startup;
disabling OSC after it has started is not supported. Over OSC, pane wrapping
is controlled by the Rex-side `wrap` setting.


REX ~

These are the defaults:

>lua
    require('rex-navigator').setup({
      -- physical keys, so the binding doesn't depend on the keyboard layout
      keys = {
        left = 'ctrl+[KeyH]',
        down = 'ctrl+[KeyJ]',
        up = 'ctrl+[KeyK]',
        right = 'ctrl+[KeyL]',
      },
      -- Lua patterns matched against the focused program's name
      programs = { '^n?vim$', '^view$', '^n?vimdiff$' },
      -- continue from the opposite edge when no pane lies that way
      wrap = false,
    })
<

Keys you change on one side need to match on the other.


USAGE                            *rex-navigator.nvim-rex-navigator.nvim-usage*

Press `ctrl-h`, `ctrl-j`, `ctrl-k`, or `ctrl-l` to move left, down, up, or
right, whether the next split is a Neovim window or a Rex pane.

Run `:checkhealth rex-navigator` to check that Neovim is running inside Rex and
can find the `rex` executable.


HOW IT WORKS              *rex-navigator.nvim-rex-navigator.nvim-how-it-works*

Each `ctrl-h/j/k/l` binding in Rex asks the focused terminal for its foreground
process. When the process name matches one of `programs`, the binding returns
`false` and Rex sends the key to the terminal, so Neovim gets it. Otherwise the
binding moves focus with the server’s `session.focus_direction` method.

In a local Rex session, the Neovim key runs `wincmd`. If the window doesn’t
change, Neovim runs `rex do` with the same `session.focus_direction` call,
using the `REX_SESSION` environment variable that Rex sets for programs it
starts.

Over SSH without a local Rex session, Neovim publishes its split directions
and mode over OSC 7501. Rex forwards navigation keys when Neovim can handle
them and moves between Rex panes at split edges. No Rex executable is needed
on the remote host in this mode.

Both sides call the server method rather than Rex’s `pane.focus.*` actions.
Those actions always wrap, and running them from the command line needs Rex’s
Remote Control setting turned on.


DEVELOPMENT                *rex-navigator.nvim-rex-navigator.nvim-development*

Run tests and lint:

>shell
    make test
    make lint
<

The tests run the Rex side against a fake `rex` table, so they don’t need
Rex.

Enable the local git hooks (one-time setup):

>shell
    git config core.hooksPath .githooks
<

This activates a pre-commit hook that checks staged Lua files with stylua
<https://github.com/JohnnyMorganz/StyLua>.
